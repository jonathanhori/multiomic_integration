# Running the simulation studies on Hoffman2 (Slurm)

Hoffman2's production cluster runs **Slurm** (`sbatch`, `#SBATCH`); Grid Engine (`qsub`,
`#$`) is the legacy cluster. The job scripts here are Slurm scripts (`*.slurm`); the
older `*.sh` scripts in this folder are Grid Engine and are not used.

| File | What it is |
|---|---|
| `submit_controlled_study.slurm` | controlled study: two-factor study, single-factor grid (strength on target), high-PVE + weak study (378 tasks) |
| `submit_survival.slurm` | survival study, log-normal AFT (336 tasks) |
| `hoffman2_env.sh` | job environment (modules, conda environment); the one place to edit versions |
| `environment_hoffman2.yml` | conda environment for Linux (the repository's `environment.yml` is a macOS export) |
| `setup_hoffman2.sh` | one-time setup: symlink, environment, MOFA2, checks, optional smoke run |

## Storage

- `$HOME` is 60 GB; the studies need roughly 60-80 GB (data generated by the tasks plus
  saved fits). Keep the repository in **`$SCRATCH`** (2 TB).
- Files in `$SCRATCH` older than **14 days may be deleted**. Copy the results back when
  the jobs finish (step 6). All data are regenerated from fixed seeds, so a purge costs
  time, not results.
- The code and R scripts find the repository at `~/multiomic_integration`; the setup
  script links that path to the copy in `$SCRATCH`.
- The software is in `$SCRATCH/software` as well: the conda environment, the R library
  (MOFA2), MOFA's Python backend and the download caches (`cluster/hoffman2_env.sh`).
  On 2026-11-24 `$HOME` was too slow to install into (a 3 h setup job timed out in pip),
  and it has only ~15 GB free. After a pause of two weeks or more, rerun
  `cluster/setup_hoffman2.sh`: it rebuilds whatever the purge removed.
- Log in at **`hoffman2.oarc.ucla.edu`** for Slurm; `hoffman2.idre.ucla.edu` can land on
  the legacy Grid Engine login nodes, which have no `sbatch` / `squeue`.

## Steps

**1. Get the code and the single-factor data onto Hoffman2.** Commit and push everything
the jobs use first (the `cluster/` files and the runners); then, on Hoffman2:

```bash
cd $SCRATCH && git clone https://github.com/jonathanhori/multiomic_integration.git
```

(the repository is public, so HTTPS needs no login; the SSH address needs a GitHub SSH
key on Hoffman2). The
single-factor data are not in git; copy them from the Mac (`$SCRATCH` is
`/u/scratch/j/jonhori`):

```bash
ssh jonhori@hoffman2.idre.ucla.edu 'mkdir -p /u/scratch/j/jonhori/multiomic_integration/sim/data'
```

(`sim/data/` is not in git, and rsync creates only the last directory of the target.)

```bash
rsync -av ~/multiomic_integration/sim/data/multi_view_shared_controlled/ jonhori@hoffman2.idre.ucla.edu:/u/scratch/j/jonhori/multiomic_integration/sim/data/multi_view_shared_controlled/
```

Later code changes: commit and push on the Mac, `git pull` on Hoffman2.

**2. One-time setup**, on Hoffman2, in an interactive session (not on the login node):

```bash
h2 whoami                                   # your Slurm account(s)
srun --time=02:00:00 --cpus-per-task=2 --mem=8G --account=pi_huazhou --pty bash -l
cd $SCRATCH/multiomic_integration
module spider miniforge; h2 modules R       # check the versions in cluster/hoffman2_env.sh
bash cluster/setup_hoffman2.sh --smoke
```

The smoke run fits one replicate of each study (~10-20 min) and writes its rows to the
results folders (the full jobs then skip those replicates).

**3. Account.** Both `*.slurm` files use `--account=pi_huazhou`, the group's Slurm
account (`h2 whoami`). `sacctmgr -nP show assoc user=$USER format=account,qos` lists the
accounts you can use.

**4. Check and submit**, from the repository root (log paths are relative to it):

```bash
cd $SCRATCH/multiomic_integration
h2 validate cluster/submit_controlled_study.slurm
h2 validate cluster/submit_survival.slurm
h2 submit cluster/submit_controlled_study.slurm
h2 submit cluster/submit_survival.slurm
```

**5. Monitor**: `squeue -u $USER`, `h2 recent`, `h2 why-pending <jobid>`,
`h2 diagnose <jobid>_<task>` for a failed task; logs in `cluster/logs/`. A failed or
timed-out task is rerun with `sbatch --array=<ids> cluster/submit_...slurm`; finished
replicates are skipped.

**6. Copy the results back** to the Mac (the score CSVs are small; models and MOFA fits
are optional):

```bash
rsync -av jonhori@hoffman2.idre.ucla.edu:/u/scratch/j/jonhori/multiomic_integration/sim/results/controlled_study/ ~/multiomic_integration/sim/results/controlled_study/ --exclude models/ --exclude mofa/
rsync -av jonhori@hoffman2.idre.ucla.edu:/u/scratch/j/jonhori/multiomic_integration/sim/results/survival_study/ ~/multiomic_integration/sim/results/survival_study/ --exclude models/ --exclude mofa/
```

Then, on the Mac, `python python/sim_run_controlled_study.py --compare` checks the
single-factor rerun against `grid_default` (the no-regression check).

## Claude Code on Hoffman2 (optional)

`h2 setup-agent` (run once on Hoffman2) links the cluster's own Claude Code skill into
`~/.claude/skills` there. A Claude Code session running on Hoffman2 (for example a new
session in the desktop app over an SSH connection to Hoffman2) then knows the cluster
rules and can run `h2 whoami`, `h2 validate`, `h2 submit`, `h2 why-pending` and
`h2 diagnose` itself. Sessions on the Mac do not see that skill.
